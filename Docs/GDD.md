# 포트리스 브레이크 – 2D 턴제 포격 슈팅 게임 기획서

기준일: 2026-10-06 (원본: claude.ai 기획서 문서에서 내보냄)

## 1. 게임 개요

**포트리스 브레이크**(가칭)는 플레이어와 AI가 번갈아 포탄을 쏘며, 적을 맞히거나 발밑 지형을 무너뜨려 떨어뜨리는 2D 턴제 포격 게임이다. 6일 안에 플레이어 1유닛 대 AI 다수 유닛 대전이 끝까지 돌아가는 플레이어블 빌드를 만드는 것이 목표다.

| 항목 | 내용 |
| --- | --- |
| 장르 | 2D 턴제 포격 슈팅 (플랫포머 이동 기반) |
| 엔진 | Unity 6.6 (2D URP) |
| 플랫폼 | PC (Windows), 키보드 + 마우스 |
| 플레이 형태 | 플레이어 1유닛 vs AI 1~3유닛 (확장: 온라인 팀전, 팀당 다수 유닛) |
| 한 판 목표 시간 | 5~10분 |
| 개발 기간 | 2026-10-06 ~ 2026-10-11 (6일) |

**핵심 재미**

- **감각과 계산의 포격**: 각도, 세기, 바람을 읽어 한 발로 적을 맞히는 손맛.
- **지형을 바꾸는 전략**: 직접 맞히지 못해도 적의 발밑을 깎아 추락시킬 수 있다.
- **위치 싸움**: 30초 동안 어디로 이동해 쏠지, 다음 적 턴에 어디가 안전한지 고민한다.

**레퍼런스**: 포트리스 2(차지 포격과 바람), Worms 시리즈(파괴 지형과 추락사), 건바운드(각도 중심 조준).

## 2. 핵심 게임플레이 루프

한 판은 "이동 → 조준 → 발사 → 결과 확인"의 턴을 한쪽 진영이 전멸할 때까지 반복한다.

**매치 흐름**

1. 맵 로드, 플레이어와 AI 유닛을 스폰 지점에 배치한다.
2. 선공을 무작위로 정하고 첫 턴의 바람을 생성한다.
3. 턴을 교대로 진행한다 (턴 상세는 4장).
4. 매 턴 정산 후 승패를 확인한다.
5. 한쪽 진영이 전멸하면 결과 화면으로 넘어간다 (재시작 / 타이틀).

**한 턴 안에서 플레이어가 하는 일**

1. 상황 파악: 적 위치, 바람, 지형을 본다.
2. 이동: 사거리나 각도가 좋은 자리로 이동하거나 엄폐한다.
3. 조준과 차지: 각도를 맞추고 공격 키를 눌러 세기를 모은다.
4. 발사와 관전: 탄환이 날아가고 지형이 깎이는 것을 본다.
5. 다음 적 턴을 대비해 결과를 기억한다 (다음 조준의 기준점).

## 3. 캐릭터와 조작

캐릭터는 좌우 이동과 점프만 하는 단순한 플랫포머 조작이며, 턴 제한 시간(30초) 안에서는 이동 거리 제한 없이 자유롭게 움직일 수 있다.

**조작키**

| 행동 | 키보드 (기본) | 마우스 (선택) | 비고 |
| --- | --- | --- | --- |
| 좌우 이동 | A / D 또는 ← / → | — | 제한 시간 내 자유 이동 |
| 점프 | W | — | 지상에서만 가능 |
| 조준 각도 조절 | ↑ / ↓ | 커서 방향으로 조준 | 0°~90°, 바라보는 방향 기준 |
| 차지 및 발사 | Space 누르기 → 떼기 | 왼쪽 버튼 누르기 → 떼기 | 게이지 왕복, 뗀 순간의 세기로 발사 |
| 무기 선택 | 1~4 | 휠 또는 슬롯 클릭 | 5장 무기 표 순서 |
| 카메라 둘러보기 | Shift + 방향키 | 화면 가장자리로 커서 이동 | 자기 턴에만 |
| 줌 | Q / E | 휠 (Ctrl 누른 상태) | — |
| 일시정지 | Esc | — | — |

**기본 능력치 (초기 밸런스 값)**

| 항목 | 값 |
| --- | --- |
| HP | 100 |
| 이동 속도 | 3 유닛/초 |
| 점프 높이 | 약 1.5 유닛 |
| 낙하 데미지 | 없음 (단순화) |

**차지 규칙**

- 공격 키를 누르는 동안 세기 게이지가 0%와 100% 사이를 왕복한다 (편도 1.5초).
- 키를 떼는 순간의 세기로 발사한다.
- 100%에 도달하면 다시 내려가므로, 원하는 세기에 맞춰 키를 떼는 타이밍이 실력 요소가 된다.

**사망 규칙**

- HP가 0 이하가 되면 사망한다.
- 맵 아래 데드라인(화면 밖 낙하 판정선)을 넘으면 HP와 관계없이 즉시 사망한다.
- 사망한 유닛은 턴 순서에서 제외된다.

## 4. 턴 시스템

한 턴은 30초 행동 단계 뒤 발사나 시간 초과로 끝나고, 모든 움직임이 멈춘 뒤 다음 유닛에게 넘어간다.

```
[턴 시작: 바람·타이머 초기화]
   → [행동 단계 30초: 이동·점프·조준]
        ├─ 차지 시작 → [차지·발사: 타이머 정지] → [탄환 비행: 카메라 추적] → [착탄·폭발: 지형 깎기 → 피해 → 넉백] → [정산]
        └─ 30초 경과·미발사 ─────────────────────────────────────────────────────────────→ [정산]
[정산: 모든 움직임이 멈출 때까지, 최대 5초]
   → <승패 판정>
        ├─ 진행 → 다음 유닛의 [턴 시작]
        └─ 한 진영 전멸 → [결과 화면: 승리 / 패배]
```

착탄 직후 바로 턴을 넘기지 않고 정산 단계를 두는 이유는, 넉백과 추락이 끝나야 사망과 승패를 정확히 판정할 수 있기 때문이다.

**턴 규칙**

- 턴 순서: 진영 단위로 교대한다. 플레이어 → AI 유닛 A → 플레이어 → AI 유닛 B …처럼, AI 진영은 자기 차례마다 살아 있는 유닛을 하나씩 순서대로 돌린다.
- 제한 시간: 30초. 차지를 시작하면 타이머가 멈춘다.
- 시간 초과: 발사 없이 정산 단계로 넘어간다.
- 정산: 모든 유닛과 탄환이 멈출 때까지 기다리고, 5초가 지나면 강제로 진행한다.
- 발사 후에는 이동할 수 없다.
- 자기 턴에 스스로 떨어져도 사망하며, 그 턴은 즉시 정산으로 넘어간다.

## 5. 무기와 탄환

모든 탄환은 중력과 바람의 영향을 받는 포물선으로 날아가고, 지형이나 유닛에 닿으면 원형으로 폭발한다. MVP는 기본 포탄 하나로 완성하고, 나머지 무기는 일정에 여유가 있을 때 추가한다.

**탄도 규칙**

- 발사 속도 = 최소 속도 + (최대 속도 − 최소 속도) × 차지 비율. 초기값은 최소 4, 최대 20 유닛/초.
- 탄환은 물리 엔진에 맡기지 않고 중력·바람 공식으로 매 프레임 직접 이동시킨다. AI 시뮬레이션(8장)과 궤적을 일치시키기 위해서다.
- 바람은 턴마다 −5~+5 단계 중 무작위로 정해지며, 탄환에 수평 방향 가속을 준다 (1단계당 0.4 유닛/초²).
- 맵 좌우 경계 밖이나 데드라인 아래로 나간 탄환은 폭발 없이 사라지고 턴이 넘어간다.

**무기 목록**

| 무기 | 데미지 | 폭발 반경 | 사용 횟수 | 특징 | 단계 |
| --- | --- | --- | --- | --- | --- |
| 기본 포탄 | 35 | 1.5 유닛 | 무제한 | 기본 무기 | MVP |
| 대형 포탄 | 50 | 2.5 유닛 | 매치당 2회 | 지형을 크게 깎아 추락 유도용 | 확장 |
| 3연발탄 | 20 × 3 | 1.0 유닛 | 매치당 1회 | 발사 각도 ±5°로 3발 동시 발사 | 확장 |
| 굴착탄 | 30 | 1.2 유닛 | 매치당 1회 | 지형을 1.5초 파고든 뒤 폭발 | 확장 |

**폭발 판정**

- 데미지는 폭발 중심 100%에서 반경 끝 30%까지 거리에 비례해 줄어든다.
- 반경 안의 유닛은 폭발 중심 반대 방향으로 넉백된다. 넉백으로 낭떠러지에 떨어질 수 있다.
- 자기 자신도 피격된다 (근접 사격의 리스크).
- 처리 순서: 지형 깎기 → 데미지 → 넉백. 지형을 먼저 깎아야 넉백된 유닛이 새 지형 기준으로 떨어진다.

## 6. 파괴 지형 시스템

지형은 픽셀 텍스처로 만들고, 폭발 지점 주변 픽셀을 원형으로 지운 뒤 해당 구역의 충돌체만 다시 만든다. 기술 리스크가 가장 크므로 1일차에 프로토타입으로 먼저 검증한다.

**동작 규칙**

- 폭발 반경 안의 지형 픽셀은 모두 사라진다 (알파값 0).
- 지지할 바닥이 사라진 유닛은 중력에 따라 떨어진다.
- 공중에 뜬 지형 조각은 떨어뜨리지 않고 그대로 둔다 (Worms 방식, 구현 단순화).
- 맵 맨 아래에는 파괴 불가 지형이 없다. 바닥까지 뚫리면 그 구멍으로 추락할 수 있다.

**구현 방식 비교**

| 방식 | 원리 | 장점 | 단점 |
| --- | --- | --- | --- |
| **텍스처 + 충돌체 재생성 (채택)** | Texture2D 픽셀을 지우고, 바뀐 청크의 PolygonCollider2D를 다시 생성 | 모양이 자연스럽고 자료가 많음 | 충돌체 재생성 비용 관리 필요 |
| Tilemap 셀 삭제 | 작은 타일 단위로 지형을 구성하고 범위 안 타일 삭제 | 구현이 가장 쉬움 | 원형 폭발이 계단처럼 깨져 보임 |
| 마칭 스퀘어 메시 | 밀도 격자에서 윤곽선을 계산해 메시와 EdgeCollider2D 생성 | 성능과 품질이 좋음 | 알고리즘 구현 부담이 큼 |

**채택안 구현 단계**

1. 맵 이미지를 64×64 픽셀 청크로 나누고, 청크마다 SpriteRenderer와 PolygonCollider2D를 둔다.
2. 텍스처는 Read/Write를 켜고, 런타임에 복사본을 만들어 수정한다 (원본 에셋 보호).
3. 폭발 시 반경이 걸치는 청크만 찾아 원 안의 픽셀 알파를 0으로 바꾸고 `Apply()`한다.
4. 바뀐 청크는 `Sprite.Create`로 스프라이트를 다시 만들고 PolygonCollider2D를 새로 붙여 물리 모양을 갱신한다.
5. 충돌체 재생성이 느리면 4단계만 마칭 스퀘어 기반 윤곽 계산으로 교체한다.

**검증 기준 (1일차 스파이크)**: 연속 20회 폭발에서 프레임 드랍 없이 캐릭터가 새 지형 위를 걷고 구멍으로 떨어지면 통과.

## 7. 맵과 환경 요소

MVP는 손으로 그린 맵 1장으로 진행하고, 바람은 MVP에 포함, 서든데스는 확장 요소로 둔다.

**맵 구성**

- 크기: 가로 약 3화면, 세로 약 1.5화면 분량.
- 지형: 언덕, 골짜기, 떠 있는 섬 2~3개로 고저차를 만든다.
- 맵 아래는 물(또는 허공)이며 데드라인이 있다.
- 좌우 끝은 보이지 않는 벽으로 막지 않는다. 밀려나면 떨어진다.

**스폰**

- 플레이어는 맵 왼쪽 1/3, AI 유닛들은 오른쪽 1/3 구역의 지정 지점에 서로 겹치지 않게 무작위로 스폰한다.
- 플레이어와 가장 가까운 AI 유닛 사이 거리는 최소 1화면 이상 떨어뜨린다.

**카메라**

- 턴 시작 시 현재 턴 유닛을 따라간다.
- 발사 후에는 탄환을 따라가고, 착탄 후 1초 머문 뒤 다음 턴 유닛으로 이동한다.
- 줌과 맵 둘러보기를 키보드와 마우스 모두로 지원한다 (자기 턴에만, 키는 3장 조작키 표).

**서든데스 (확장)**

- 전체 15턴이 지나면 매 턴 수면이 0.5 유닛씩 올라와 장기전을 끝낸다.

## 8. AI 설계

AI는 여러 각도와 세기로 탄도를 미리 시뮬레이션해 적에게 가장 가까이 떨어지는 조합을 고르고, 난이도만큼 오차를 섞어 쏜다. 플레이어와 같은 입력 인터페이스로 유닛을 조종하므로 별도 규칙이 필요 없다.

**행동 단계**

1. **대상 선택**: 현재 구성에서는 플레이어 유닛이 유일한 대상이다 (멀티플레이 확장 시 가장 가까운 적).
2. **이동 판단**: 현재 자리에서 쏠 만한 궤적이 없으면 대상 쪽으로 최대 3 유닛 이동한다.
3. **조준 계산**: 각도 15°~75°를 5° 간격, 세기를 10% 간격으로 나눠 궤적을 시뮬레이션한다 (최대 13 × 10 = 130개). 바람과 중력을 반영하고, 궤적이 지형에 먼저 막히면 그 지점을 착탄점으로 본다.
4. **선택**: 착탄점이 대상에 가장 가까운 조합을 고른다. 자기 자신이나 아군 AI 유닛이 폭발 반경에 들어가는 조합은 제외한다.
5. **오차 적용**: 난이도에 따라 각도와 세기에 무작위 오차를 더한다.
6. **연출 후 발사**: 1~2초 생각하는 척 뜸을 들이고, 각도를 천천히 돌린 뒤 차지해서 쏜다.

**난이도별 차이**

| 난이도 | 세기 오차 | 각도 오차 | 바람 반영 |
| --- | --- | --- | --- |
| 쉬움 | ±15% | ±8° | 무시 |
| 보통 | ±7% | ±4° | 반영 |
| 어려움 | ±2% | ±1° | 반영 |

시뮬레이션은 Physics2D를 직접 돌리지 않고, 같은 공식으로 0.02초 단위 위치를 계산한 뒤 구간마다 Physics2D.Linecast로 지형 충돌을 확인한다. 실제 발사 궤적과 어긋나지 않도록 탄환도 같은 공식을 쓰는 것이 핵심이다.

## 9. UI/UX

화면에는 턴 정보, 조준 정보, 유닛 상태 세 가지만 보여주고, 타격감은 카메라 흔들림과 데미지 숫자로 전달한다.

**HUD 요소**

| 요소 | 위치 | 내용 |
| --- | --- | --- |
| 턴 타이머 | 화면 상단 중앙 | 남은 초, 5초 이하일 때 빨간색 + 경고음 |
| 현재 턴 표시 | 타이머 아래 | "내 턴" / "AI 턴" |
| 바람 | 화면 상단 우측 | 방향 화살표 + 세기 단계 (−5~+5) |
| HP 바 | 각 유닛 머리 위 | 현재 HP, 피격 시 감소 연출 |
| 조준선 | 유닛 주변 | 현재 각도를 나타내는 선, 각도 숫자 |
| 파워 게이지 | 화면 하단 중앙 | 차지 비율, 지난 턴 세기 표시선 |
| 무기 슬롯 | 화면 하단 좌측 | 무기 아이콘, 남은 횟수 |

지난 턴 세기 표시선은 포트리스류의 "기준점 조준"을 돕는 장치로, 직전 사격 결과를 바탕으로 세기를 조절하게 해준다.

**화면 흐름**

1. 타이틀 → 2. 난이도 선택 → 3. 게임 → 4. 결과(승리/패배, 재시작/타이틀). 게임 중 Esc로 일시정지 메뉴를 연다.

**피드백 연출**

- 폭발: 파티클 + 카메라 흔들림 (데미지에 비례).
- 피격: 데미지 숫자 팝업, 유닛 깜박임.
- 추락사: 물보라 효과와 "OUT" 문구.
- 턴 전환: 상단 배너가 0.8초 동안 표시.

## 10. 시스템 아키텍처

TurnManager가 턴마다 조종권을 넘기고, 플레이어 입력과 AI는 같은 `IUnitController` 인터페이스로 유닛을 조종한다. 이 분리 덕분에 나중에 네트워크 입력을 같은 자리에 끼울 수 있다.

```
GameManager (매치 시작·종료, 승패 판정)
   │ 매치 시작 ↓        ↑ 정산 후 승패 확인
TurnManager (턴 순서 · 30초 타이머 · 상태 전환)
   ├─ 이벤트 → UIManager (HUD 갱신, 이벤트 구독)
   ├─ 이벤트 → CameraController (유닛·탄환 추적, 이벤트 구독)
   └─ 턴 시작 시 조종권 부여 ↓
IUnitController (유닛을 조종하는 공통 인터페이스)
   ├─ PlayerInputController (키보드·마우스 입력)
   ├─ AIController (궤적 시뮬레이션 후 조준)
   └─ NetworkController (확장 예정 · 원격 입력 수신)
   │ 이동·조준·발사 명령 ↓
Unit (이동·점프·HP·사망)
   → 발사 → Projectile (탄도 공식으로 비행)
             → 착탄 → ExplosionResolver (착탄 처리 순서 관리)
                         ├─ 지형 깎기 → DestructibleTerrain (청크 픽셀 깎기·충돌체 갱신)
                         └─ 피해·넉백 적용 → Unit
```

**주요 이벤트**: `OnTurnStarted`, `OnTurnEnded`, `OnWindChanged`, `OnUnitDamaged`, `OnUnitDied`, `OnMatchEnded`. UI와 카메라는 이 이벤트만 구독하고 게임 로직을 직접 호출하지 않는다.

**설계 원칙**

- 밸런스 값(HP, 데미지, 폭발 반경, 차지 시간)은 ScriptableObject로 빼서 코드 수정 없이 조정한다.
- 탄도 공식은 정적 함수 하나로 두고 Projectile과 AIController가 공유한다.
- 무기는 `WeaponData`(ScriptableObject) + 공통 Projectile 구조로 만들어 무기 추가를 데이터 작업으로 끝낸다.

## 11. 멀티플레이 확장 계획

이번 6일 일정에서는 멀티플레이를 구현하지 않고, 나중에 붙일 수 있도록 유닛 조종을 컨트롤러 인터페이스로 분리해 두는 것까지만 한다.

**권장 구성**: Netcode for GameObjects + Unity Relay/Lobby, 호스트가 서버 역할을 겸하는 2인 대전.

**동기화 원칙**

- 턴제이므로 매 프레임 상태를 보내지 않는다. 현재 턴 플레이어의 입력 결과만 보낸다.
- 이동은 위치를 주기적으로 동기화하고, 발사는 "각도, 세기, 무기, 발사 위치" 한 번만 전송한다.
- 바람은 호스트가 정해 턴 시작 때 알린다.
- 지형은 텍스처를 보내지 않고 "폭발 좌표 + 반경" 목록을 보내 각자 깎는다. 같은 입력이면 같은 결과가 나오도록 지형 처리를 결정적으로 만든다.
- 데미지, 사망, 승패 판정은 호스트만 계산하고 결과를 알린다.

**지금 해둘 준비**: 플레이어 입력, AI, (향후) 네트워크가 모두 같은 `IUnitController` 인터페이스로 유닛을 조종하게 만든다 (10장).

## 12. 개발 범위와 일정

10월 10일까지 MVP를 끝까지 플레이 가능하게 만들고, 10월 11일은 폴리싱과 빌드에만 쓴다. 가장 불확실한 파괴 지형을 1일차에 먼저 검증한다.

**MVP 범위**

- 포함: 맵 1장, 플레이어 1유닛 vs AI 1~3유닛 대전, 이동·점프·조준·차지 발사, 기본 포탄, 바람, 파괴 지형, 30초 턴, HP·추락 사망, 승패, 기본 HUD, 난이도 3단계.
- 제외 (확장): 추가 무기 3종, 서든데스, 사운드 고도화, 멀티플레이.

**일자별 계획**

## 13. 리스크와 미결 사항

가장 큰 리스크는 파괴 지형의 충돌체 갱신 성능이며, 실패 시 Tilemap 방식으로 내려가는 대안을 둔다.

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 충돌체 재생성이 느림 | 폭발마다 프레임 끊김 | 청크 크기 축소, 그래도 느리면 Tilemap 방식으로 전환 |
| 캐릭터가 깎인 지형 경계에 끼임 | 이동 불가, 턴 낭비 | CapsuleCollider2D 사용, 끼임 감지 시 위로 살짝 밀어내기 |
| AI 시뮬레이션과 실제 궤적 불일치 | AI가 엉뚱한 곳에 쏨 | 탄환과 AI가 같은 탄도 함수를 공유 |
| 일정 지연 | MVP 미완성 | 10/9 종료 시점에 미완 기능은 확장으로 이월 |

**결정이 필요한 사항**

- [x] 차지 방식: 왕복 게이지로 결정 (3장 반영)
- [x] 조준 방식: 모든 행동을 키보드로 가능하게 하고 마우스는 보조 입력으로 결정 (3장 반영)
- [x] 팀 구성: 플레이어 1유닛 고정, AI는 여러 유닛으로 결정 (멀티플레이는 팀당 다수 유닛)
- [x] 이동 게이지 없음으로 결정 (제한 시간 내 자유 이동, 3장 반영)
- [x] 아트 리소스: 무료 CC0 에셋 사용 (후보는 아래 표)

**아트 리소스 후보**
